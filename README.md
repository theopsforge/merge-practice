# Git & GitHub Learning Portfolio

## About This Repository

Welcome to my Git and GitHub learning portfolio.

This repository documents my practical journey toward developing professional Git and DevOps skills.

Rather than simply collecting commands or theoretical explanations, I use this repository to practise Git workflows, understand how version control operates, experiment with different approaches, troubleshoot mistakes, and preserve evidence of my learning progress.

My objective is to develop the practical knowledge and confidence needed to use Git effectively in real software development and DevOps environments.

## Learning Objectives

The main objectives of this repository are to develop practical experience with:

- Git fundamentals and repository management.
- Branch creation, switching, and management.
- Commit history and commit relationships.
- Fast-forward and three-way merges.
- Merge conflict resolution.
- Rebasing and understanding rewritten commit history.
- Git reset and its different modes.
- Restoring files and managing staged changes.
- Reverting commits while preserving shared history.
- Temporarily saving unfinished work with Git stash.
- Remote repositories and GitHub collaboration.
- Pushing, pulling, and synchronising repositories.
- `.gitignore` and repository hygiene.

## Why This Repository Preserves Its Git History

This repository is a practical learning portfolio documenting my journey toward mastering Git and GitHub as part of my DevOps development.

Rather than combining all exercises into a single branch, I have intentionally preserved the relevant branches and commit history. Each branch represents part of my hands-on learning and demonstrates how different Git operations work in practice.

The repository preserves examples of:

- **Branching:** Creating and working with independent development branches.
- **Merging:** Bringing changes together through fast-forward and three-way merges.
- **Merge commits:** Preserving the history and relationships between merged branches.
- **Rebasing:** Reapplying commits onto another base and observing how commit history changes.
- **Resetting:** Moving branch references and understanding the effects of different reset modes.
- **Restoring:** Recovering file contents and managing staged and unstaged changes.
- **Reverting:** Reversing a previous commit while preserving the original commit in history.
- **Stashing:** Temporarily saving unfinished work and restoring it later.

The purpose of preserving this history is to make the repository a transparent record of practical learning, experimentation, mistakes, corrections, and progress.

The `main` branch serves as the primary branch, while the other relevant branches remain available to demonstrate specific exercises and Git workflows.

This is a learning and mastery portfolio, not a production application. Its history is intentionally retained so that anyone exploring the repository can examine the commits, branches, and relationships between them.

## Learning Approach

My learning approach focuses on:

1. Understanding the purpose of each Git operation.
2. Predicting what a command will do before executing it.
3. Practising commands in a controlled local repository.
4. Inspecting commit history and branch relationships.
5. Verifying results through Git commands.
6. Learning from mistakes and correcting misunderstandings.
7. Applying the concepts to practical development workflows.

The goal is not simply to execute commands, but to understand what Git is doing and why.
